# МЕХАНИКА: Пульс-античит (Heart Gate)

> Пульс доказывает, что часы на руке живого человека во время записи удара. Это главный шлюз валидности Dojo-сессии. Подробности записи ударов — в `MECHANIC_COMBAT_RECORDING.md`, общий античит — в `docs/05-security/ANTICHEAT.md`.

---

## 1. ПОЧЕМУ ПУЛЬС — ГЛАВНЫЙ СИГНАЛ

| Способ обмана | Акселерометр | Пульс |
|---|---|---|
| Трясут часы в руке, не надевая | ✅ нормальные удары | ❌ нет сигнала / артефакт |
| Часы на столе, бьют по столу рядом | ⚠️ похожий профиль | ❌ нет контакта с кожей |
| Примотали к мешку/пружине | ✅ сильные ускорения | ❌ нет кожи / хаотичный пульс |
| Проигрывают записанный буфер | ✅ (через твик) | ❌ нет пульса |
| **Игрок реально боксирует** | ✅ | ✅ повышенный пульс |

Пульс — единственный сигнал, который **невозможно подделать**, не надев часы на живое тело. Поэтому он — **gate (шлюз)**.

---

## 2. АРХИТЕКТУРА

### 2.1. Pre-flight (на экране Dojo, ~8 сек)
До начала записи часы 5–10 секунд замеряют baseline-пульс.
```
HR_baseline     = median(HR samples за 8 сек при стабильном сигнале)
contactConfidence = доля валидных сэмплов (≥ 0.85 = контакт хороший)
```

- Оптический сенсор прогревается (cold start 5–15 сек).
- Получаем персональный baseline `HR_rest` (у спортсменов может быть 45–55 — не назовём их читерами).
- Проверяем надёжность контакта (сигнал «горит» постоянно, без просадок).

**Если `contactConfidence < 0.85` → просим поправить часы.** Запись не стартует.

### 2.2. Окно записи (5–8 сек)
Считываем пульс параллельно с акселерометром/гироскопом. Сохраняем:
- `HR_present` — % времени с валидным пульсом;
- `HR_mean` — средний пульс за окно;
- `HR_delta` — `HR_mean − HR_baseline`;
- `HR_consistency` — низкая вариативность / отсутствие «дыр».

### 2.3. Вердикт

```
heartGate =
    (HR_present     ≥ 0.80)                    // пульс виден почти всё время
    AND (HR_mean    ≥ HR_baseline + 8)         // реальная нагрузка
    AND (HR_mean    ≥ 55)                      // отсечка «на столе»
    AND (contactConfidence ≥ 0.85)             // контакт с кожей
```

Все 4 условия → VALID. Иначе — запись отклоняется с человекочитаемой причиной.

### 2.4. Spirit Bonus (мягкий бонус за нагрузку)
Даже валидная запись получает модификатор «боевого духа»:
```
spiritBonus = clamp((HR_delta - 8) / 40, 0, 0.20)   // до +20% к качеству
heartScore  = heartGate ? (0.5 + spiritBonus) : 0   // 0.5..0.70
```

Игрок, который реально разогнался (140+ ударов), получает буст. Это превращает фитнес-нагрузку в геймплейное вознаграждение.

## 3. ГРАНИЧНЫЕ СЛУЧАИ

| Случай | Решение |
|---|---|
| Спортсмен с resting HR 48 | `HR_mean ≥ 55` сработает при лёгкой активности; baseline-дельта защищает |
| Холодные руки, плохой кровоток | `contactConfidence` падает → просим «потёреть запястье, надеть плотнее»; 1 повтор |
| Дешёвый ремешок, проскальзывает | мягкий повтор, не блокировка |
| Сенсор не откалиброван | Pre-flight это покажет; запись не стартует, а не отваливается в конце |
| Дети (аудитория тамагочи) | Их resting HR выше (80–110), дельта работает даже лучше |
| Реально маленькая активность | Дельта ≥8 — низкий порог; сработает почти у всех |

**Принцип:** лучше пропустить подозрительную запись один раз, чем заблокировать честного игрока. Пульс — шлюз, но гуманный.

**Метрика для отслеживания:** доля успешных pre-flight с первой попытки (без повтора). Это прямой индикатор фрикции перед главным USP-циклом — стоит мониторить с первого плейтеста, а не только после запуска.

---

## 4. БАТАРЕЯ И ПРИВАТНОСТЬ

- Оптический пульс-сенсор — **только во время Dojo**, не фоном. 8 сек pre-flight + 8 сек записи ≈ 16 сек за сессию.
- Явный consent при первом запуске: *«Для записи приёмов нужен пульс — он докажет, что часы на руке, и даст бонус к качеству»*.
- Сырой сигнал пульса **не покидает устройство** — на сервер уходят только производные: `HR_present`, `HR_mean`, `HR_delta`, `contactConfidence` (4 числа).

---

## 5. ПЛАТФОРМЕННАЯ РЕАЛИЗАЦИЯ

| Платформа | API пульса | Замечание |
|---|---|---|
| **watchOS** | `HKWorkoutSession` + `HKLiveWorkoutBuilder`, тип `HKQuantityTypeIdentifier.heartRate` | Единственный путь к realtime-пульсу. CoreMotion пульс **не отдаёт** |
| **Wear OS** | `Sensor.TYPE_HEART_RATE` (Samsung Health Sensors API для низкого latency) | Требует `BODY_SENSORS` permission |
| **Shared Core** | Принимает уже посчитанные 4 метрики → вердикт и бонусы | Единая формула на всех платформах |

> ⚠️ Для realtime-пульса во время записи на watchOS нужен **активный WorkoutSession** (иначе данные с задержкой 5–30 сек). На Wear OS — Samsung Health Sensors API даёт ~1 Гц realtime.

---

## 6. UX

1. **Dojo → «Записать приём»** → часы: *«Надень часы плотнее и расслабься…»*
2. **Pre-flight (8 сек):** пульс появляется, загорается зелёный значок ❤️ + число.
3. Если контакт плохой → *«Поправь часы на запястье»* (1 повтор, без штрафа).
4. **Запись (3-2-1):** снизу полоска пульса, сверху — индикатор ударов.
5. После записи:
   - 🟢 *«Чистый удар! Дух +12%»* → Technique Card создана.
   - 🔴 *«Не получилось зафиксировать пульс. Проверь посадку часов.»* → мягко, без наказания.
6. На Technique Card показывается **Spirit-бейдж**: «🔥 Adrenaline» если HR был высоким.

## 7. ВКЛАД В ФОРМУЛУ КАЧЕСТВА

```
qualityScore =
      0.40 · normPower
    + 0.25 · precision
    + 0.12 · comboScore
    + 0.08 · rhythmScore
    + 0.15 · heartScore         // ← без валидного пульса = 0
```

Без валидного пульса `heartScore = 0` → качество резко падает, и даже технически хорошая запись получает максимум Common/Uncommon. **Чит без пульса экономически невыгоден.**
