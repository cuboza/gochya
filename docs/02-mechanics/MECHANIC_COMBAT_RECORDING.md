# МЕХАНИКА: Запись ударов с акселерометра (Боевой датчик / Dojo)

> **USP-1.** Игрок записывает реальные удары в воздухе. Акселерометр + гироскоп + пульс превращают движение в **Technique Card** для PvP.

---

## 0. ДВА ПУТИ К КАРТАМ (телефон-дублёр)

> **Проектное решение.** Телефон (Android/iPhone) — **полноценный клиент**, проходимый
> без часов (`CLIENT_COMPANION.md`). Но запись удара требует акселерометра **на запястье**
> и пульса, поэтому Dojo существует только на часах. Чтобы телефонные игроки —
> большинство аудитории — не были отрезаны от боевой системы, карты добываются
> **двумя путями**, и запись удара даёт **качество и персонализацию, а не монополию
> на силу**.

| Путь | Где | Что даёт | Потолок редкости |
|---|---|---|---|
| **Игровая добыча** | телефон **и** часы | карты за задания, PvP-награды, дневную активность, гачу | Common … **Epic** |
| **Запись удара (Dojo)** | **только часы** | карты «твоего стиля» + spirit-бонус + доступ к вершине шкалы | Common … **Mythic** |

**Как это удерживает баланс и снимает pay-to-win:**

1. **Телефонный игрок конкурентоспособен.** Боевая сила — это `effectivePower`
   (`CORE_FORMULAS.md` §5.1): статы питомца + сила карт + снаряжение. Карт Epic,
   добытых игрой, статов от бридинга и снаряжения достаточно для любой лиги;
   матчмейкинг сводит равных по power.
2. **Часы дают преимущество в эффективности, а не пропуск.** Записанная карта может
   достичь Legendary/Mythic и несёт spirit-бонус — но за ту же `effectivePower`
   соперник будет равным. Часы = «за то же усилие чуть эффективнее и это *мой* стиль»,
   а не «без часов ты проиграешь».
3. **Signature-приём — только записанная карта.** Персонализация «питомец дерётся
   *твоим* ударом» остаётся эксклюзивом часов, но это косметика идентичности,
   а не боевое превосходство (см. §8).
4. **Платёж не открывает силу, которой нет иначе.** Гача даёт карты того же потолка
   (Epic), что и бесплатная игровая добыча — то есть остаётся ускорителем, а не
   единственным путём. Обещание `EXECUTIVE_SUMMARY.md` «платное не даёт
   гарантированной победы» сохраняется на обеих платформах.

Числа потолков и источников — в `BALANCE.md` §5.3. Остальной документ описывает
**путь записи** (Dojo); игровая добыча карт — в `GDD.md` §6 и `BALANCE.md`.

## 1. ФАНТАЗИЯ ИГРОКА

Твой питомец — твой ученик. Ты тренируешь его, **реально** нанося удары в воздухе. Твои настоящие движения превращаются в боевые приёмы питомца, которые он использует в PvP. Каждый питомец дерётся **в твоём личном стиле** — двух одинаковых питомцев не существует.

> На телефоне без часов эта фантазия доступна в мягкой форме: карты добываются игрой,
> а «свой стиль» через запись удара открывается, когда игрок подключает часы —
> это причина их захотеть, а не барьер на входе.

Дополнительно: stealth-fitness (калории, шаги, streak'и), самовыражение, глубина PvP.

## 2. ГЕЙМПЛЕЙНАЯ ПЕТЛЯ

1. **Dojo-режим** на часах → «Записать приём».
2. Вибрация «READY», отсчёт 3-2-1, открывается окно записи 5–8 сек.
3. Игрок выполняет удар или комбо.
4. С часов уходят **только производные метрики и schema-versioned feature summary** (sample counts, duration, peaks/RMS, entropy, zero crossings, HR aggregates, classifier/build version). Сырой временной ряд не покидает устройство.
5. Сервер проверяет nonce, platform attestation, подпись payload и внутреннюю согласованность признаков до создания карты (`ANTICHEAT.md §2.1, §3.3a–b`).
5. Сервер валидирует сессию (см. `MECHANIC_HEART_GATE.md` и `ANTICHEAT.md`) и выдаёт **Technique Card**.
6. Карта попадает в **Skill Library** → игрок собирает боевой лоадаут для PvP.

## 3. ЧТО ИЗМЕРЯЕМ

- **Акселерометр** (3 оси) — линейное ускорение, **50 Гц** (нормативная частота).
- **Гироскоп** (3 оси) — вращение кисти/руки, та же частота.
- **Пульс** — доказательство «на руке» + «боевой дух» (см. `MECHANIC_HEART_GATE.md`).

За 6 секунд = ~300 сэмплов × 6 осей ≈ 1.8K float — помещается в память и обрабатывается на устройстве.

> ⚠️ **Частота — ровно 50 Гц, не «50–100».** Источник истины —
> `MECHANIC_ML_CLASSIFIER.md` §2.2. Прежнее «~50–100 Гц / ~600 сэмплов» подразумевало
> 100 Гц и вчетверо увеличивало DTW-матрицу (1.4 МБ вместо 360 КБ), ломая бюджеты
> из `MECHANIC_ML_CLASSIFIER.md` §5. Единицы измерения ускорения различаются
> по платформам — см. `MECHANIC_ML_CLASSIFIER.md` §2.2а.

## 4. КЛАССИФИКАЦИЯ ПРИЁМА (edge ML на часах)

Маленькая модель на устройстве: **TFLite Micro / ONNX Runtime / Core ML** (или DTW по шаблонам для MVP — дешевле и объяснимее).

| Параметр | Источник | Что даёт |
|---|---|---|
| **Тип удара** | классификатор (джеб, хук, апперкот, кросс, удар ногой, локоть, блок) | стихия/класс приёма |
| **Power** | пиковое |accel| в м/с² | базовый урон |
| **Speed** | время до пика | очерёдность хода в авто-битве |
| **Precision** | соответствие шаблону (form score 0–1) | модификатор урона + стабильность |
| **Combo** | число различных ударов в окне | цепочки в бою |
| **Rhythm** | дисперсия интервалов между ударами | крит, стан |

Реальные значения: пиковое ускорение удара у обычного человека ~30–80 м/с², у тренированного — 80–110+. Это даёт естественный разброс редкостей без искусственных порогов.

## 5. TECHNIQUE CARD

```
// Соответствует docs/04-core/CORE_SPEC.md §3.4 (аудит N2, N3)
struct TechniqueCard {
    id:           [u8; 16],          // UUID, fixed-size для FFI
    type:         TechniqueType,     // Jab, Hook, Uppercut, Kick, Cross, Elbow, Block
    element:      Element,           // связано с геном питомца (см. BREEDING)
    rarity:       Rarity,            // Common..Mythic (по qualityScore)
    baseDamage:   f32,               // f(power, precision, level)
    speed:        f32,               // f(executionTime) — выше = ходит раньше
    staminaCost:  u16,               // f(power)
    effect:       Effect,            // плоская структура, FFI-safe (НЕ Option<Effect> — audit N3)
    quality:      u8,                // 0..100
    owner_id:     [u8; 16],          // привязка к стилю автора (snake_case — audit N2)
    created_at:   u64,               // unix timestamp
}
// ВАЖНО: поле `signature` УБРАНО из карты (audit N2) — это свойство Loadout:
//   Loadout.signature_idx: u8   // 0..4 — индекс карты в лоадауте, которая занимает ult-слот
// Игрок назначает любую из 5 карт как signature, а не карта «сама по себе» коронная.
```

## 7. ФОРМУЛЫ

> ⚠️ **Единый источник истины — `docs/04-core/CORE_FORMULAS.md §2`.** Здесь приведены те же формулы; при расхождениях приоритет у CORE_FORMULAS.

```
qualityScore = 100 · (                              // ← множитель 100 обязателен (аудит N1)
      0.40·normPower + 0.25·precision + 0.12·comboScore + 0.08·rhythmScore + 0.15·heartScore
)                                                   // → диапазон 0..100
baseDamage     = (peakAccel / 50) · precision · typeMultiplier · techLevel
speed          = 100 / (1 + execTime_sec)
staminaCost    = round(powerRating · 2.2)
critChance     = clamp(0.02 + 0.01·comboLen + 0.05·(rhythmScore-0.5), 0, 0.35)
```

`heartScore` — из пульс-гейта (см. `MECHANIC_HEART_GATE.md`). Без множителя `100 ·` пороги `rarityFromQuality` сломаны.

---

## 8. КОРОННЫЙ УДАР (SIGNATURE MOVE / ULTIMATE)

- У каждого питомца **один слот коронного приёма** — это `Loadout.signature_idx`
  (индекс одной из 5 карт), см. §5.
- **Игрок выбирает** signature из своего лоадаута. По умолчанию UI предлагает карту
  с наибольшим `qualityScore`, но выбор можно сменить — коронной становится не «сама
  по себе лучшая карта», а та, что игрок назначил.
- Это персонализация: **твой** питомец дерётся **твоим** ударом.

> ⚠️ Прежняя формулировка «лучшая запись автоматически становится ультой»
> противоречила §5 (там signature — свойство лоадаута, выбираемое игроком)
> и `CORE_SPEC.md` §3.6 (`signature_idx` задаётся при сборке лоадаута).

## 9. ПРОГРЕССИЯ И АНТИГРИНД

- **Дневной лимит записи:** 10 сессий/день (плюс премиум-слоты за Gems/GOCHYA+).
- **Мышечная память:** повторение одного типа удара слегка поднимает потолок качества (≈ +1% за 50 повторов, кап +15%).
- Достижения: «100 джебов», «Первая Mythic-карта», «Комбо из 5».

## 11. АНТИЧИТ

Серверный расчёт боя: клиент шлёт только ID выбранных карт — урон считает ядро на сервере. Подменить карту/статы нельзя.

Валидация записи (privacy-first, audit S1 — см. `ANTICHEAT.md §3`):
- **heart gate** (главный, 60 баллов) — пульс доказывает, что часы на руке;
- **replay-detection** с серверным nonce (15 баллов);
- **клиентская энтропия** с проверкой диапазона на сервере (15 баллов);
- **rate-limit** (10 баллов);
- **вероятностный аудит типа удара** (post-factum, не блокирует).

> ⚠️ **Чего НЕТ** (audit S1): серверной спектральной подписи, гироскоп-сигнатуры на сервере — физически невозможны без передачи сырого сигнала, что нарушает privacy-first принцип. Прежние версии этого списка упоминали их — они убраны.
