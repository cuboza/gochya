# MVP — Вертикальный срез

> Скоуп первой играбельной версии. Принцип MVP: **минимум фич, максимум пути** — игрок проходит весь цикл от яйца до дуэли.

---

## 1. ЦЕЛЬ MVP

Доказать основную фантазию: **питомец растёт вместе с игроком, реальные удары становятся приёмами, в PvP эти приёмы дерутся.**

Критерий успеха MVP (внутреннее тестирование):
- Полный цикл играбелен от яйца до первой дуэли.
- Все 3 USP-механики работают: запись удара, бридинг (базовый), симбиоз с активностью.
- Производительность в бюджете на реальных устройствах (Galaxy Watch 6/7, Apple Watch S9).
- D1 retention на закрытом тесте ≥ 35%.

## 4. КРИТЕРИИ ГОТОВНОСТИ MVP (Definition of Done)

### Технические
- [ ] Shared Core: 100% формул из `CORE_FORMULAS.md` реализованы и покрыты тестами.
- [ ] CI green для всех **6 таргетов** (`ARCHITECTURE.md` §4: iOS, watchOS `arm64_32`, iOS-sim, Android, server, tests).
- [ ] Golden tests: одинаковый результат боя на всех платформах.
- [ ] Golden tests классификатора: `technique_type`, `precision` **и `peak_accel`** совпадают на обеих платформах (`MECHANIC_ML_CLASSIFIER.md` §4).
- [ ] Performance на Galaxy Watch 6: ≤ **2** сек cold start, **60** FPS, ≤ 2%/час в фоне (`CLIENT_WEAROS.md` §10).
- [ ] Ядро собирается под `arm64_32-apple-watchos` и вызывается из Swift (Gate 2) — **без полного watchOS-клиента**, он в Beta.
- [ ] Инвариант баланса стихий проверен **на каждом релизном наборе**, включая MVP-тройку (`CORE_SPEC.md` §5 №10).
- [ ] Бэкенд: 99% uptime на staging, p95 latency ≤ 300ms.

### Геймплейные
- [ ] **Телефон без часов проходит полный цикл:** регистрация → яйцо → забота → тренировка → добыча карт (без Dojo) → дуэль → награда → бридинг. Это отдельный тест-прогон — основной сценарий для большинства игроков.
- [ ] Полный цикл с часами: то же + запись удара в Dojo → карта «своего стиля».
- [ ] Бридинг: скрещивание → яйцо → вылупление.
- [ ] Симбиоз: шаги/сон учитываются, Vitality начисляется (на телефоне — с деградацией метрик запястья, `MECHANIC_SYNERGY.md` §9а).
- [ ] PvP: телефонный и часовой игрок попадают в один пул и бьются между собой.
- [ ] IAP работают на всех 3 сторах.
- [ ] Онбординг проходит новый игрок за ≤ 12 минут (флоу начинается на телефоне, `UX_UI.md` §8).

### Античит
- [ ] Heart gate: запись без валидного пульса → REJECTED (`ANTICHEAT.md` §3.0), карта не создаётся.
- [ ] Карты игровой добычи на телефоне выдаёт **сервер** (детерминированно, не клиент) — тот же server-authority, что и для боя.
- [ ] Все бои считаются на сервере.
- [ ] Ledger валют сходится (consistency check green).

### Privacy
- [ ] Consent flow для Health/Sensors.
- [ ] Сырые данные сенсоров не покидают устройство (верифицировано).
- [ ] Политика конфиденциальности опубликована.

## 6. ПОРЯДОК РАЗРАБОТКИ (фазы MVP)

### Sprint 0 (нед 1–4): Pre-production
- Финализация документации (✅ уже есть).
- Прототип Shared Core: типы + базовые формулы + golden tests.
- Архитектурные спайки: FFI под iOS и Android, hello-world сборка.

**🚨 Критические gate'ы Sprint 0 (audit F5 — без них старт невозможен):**
- **Gate 1: Wear OS натив-спайк.** На Galaxy Watch 6 запустить Filament + одну glTF-модель + прочитать accelerometer + gyroscope + HR. Замерить FPS, cold start, расход батареи за 16 сек Dojo-имитации. **Порог — то, что обещает спека:** 60 FPS / cold start ≤ 2 сек / ≤ 0.5% батареи за 16 сек (`CLIENT_WEAROS.md` §10). Не достигнуто — пересмотр Wear OS-стратегии либо понижение обещаний в спеке, но не молчаливое расхождение.
- **Gate 2: watchOS спайк — рендер И сборка ядра.** На Apple Watch S9 запустить SpriteKit + одну Rive-анимацию, замерить те же метрики. **Отдельно и обязательно:** собрать Rust-ядро под `arm64_32-apple-watchos` (tier 3, nightly + `-Z build-std`) и вызвать из Swift хотя бы одну функцию. Это единственный таргет, способный заблокировать платформу целиком (`ARCHITECTURE.md` §4).
- **Gate 3: Samsung Health Sensor SDK partner application.** Подать заявку **в первую неделю** (`RISKS.md` R16 — top-риск). Параллельно **замерить фактическую частоту и задержку `Sensor.TYPE_HEART_RATE`** на целевых устройствах. ⚠️ Работающего fallback пока нет: при задержке 5–15 сек `heartGate` (`HR_present ≥ 0.80` за 6–8 сек) непроходим, а без него запись отклоняется целиком. Нет одобрения через 4 недели → активировать план (а/б/в) из `RISKS.md` R16.
- **Gate 4: ML-датасет старт.** Набор 5 бойцов-добровольцев, начало записи 1250 эталонов (`MECHANIC_ML_CLASSIFIER.md` §3). ⚠️ 1250 записей при ML-инженере на 0.5 FTE — это самостоятельный трек на весь Sprint 0; заложить время бойцов и обработку, иначе датасет не будет готов к Sprint 5.

## 7. ВЕРТИКАЛЬНЫЙ СРЕЗ (Vertical Slice) — demo

Два параллельных сценария — их разница и есть проверка модели «телефон-дублёр + часы-апгрейд»:

**Сценарий A — только телефон (основная аудитория):**
1. Регистрация → выбор яйца → вылупление (на телефоне).
2. Кормление и тренировка (видеть рост статов).
3. Прогулка игроком → шаги зачислены → Vitality выросла (метрики телефона).
4. **Добыча карты игрой** (задание/PvP-награда) → Technique Card до Epic.
5. Сборка лоадаута → дуэль с реальным соперником → победа → награды.
6. Скрещивание 2 питомцев → инкубация → вылупление нового.
7. Покупка косметики на награды → экипировка.
8. Экран `dojo_upsell`: «подключи часы, чтобы записывать свои удары».

**Сценарий B — телефон + часы (апгрейд):** то же, плюс
4'. **Запись удара в Dojo на часах** → Technique Card «своего стиля» (Legendary/Mythic + spirit-бонус), назначение signature.

Сценарий A **validates USP-2 и USP-3 и весь PvP без часов**; сценарий B добавляет
**USP-1**. Вместе они доказывают, что телефонный игрок конкурентоспособен, а часы —
осмысленный, но не обязательный апгрейд.
