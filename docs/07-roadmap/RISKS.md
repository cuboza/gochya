## 2. ДЕТАЛИЗАЦИЯ ТOP-5 РИСКОВ

### R1. Батарея/перформанс на 2 рантаймах ⚠️
**Проблема:** Kotlin/Filament (Wear OS) и Swift/SpriteKit (watchOS) по-разному работают с GPU/CPU; маленький экран и ограниченная батарея. *(audit S3: Unity убран — теперь оба клиента нативные, что снижает риск.)*

**Митигация:**
- Performance-бюджет определён с дня 1 (`CLIENT_*.md`).
- Тестирование на реальных устройствах (Galaxy Watch 6/7, Apple Watch S9/Ultra) каждую неделю.
- **Sprint 0 gate** (см. `MVP.md`): Wear OS Filament-спайк и watchOS SpriteKit-прототип с замерами до старта полного производства.
- AOD: 1 FPS, монохром, минимум элементов.
- Dojo: сенсоры включены только на 16 секунд, экран dim во время записи.
- Background: нулевой поллинг игрой, только системные health-aggregates.
- Профилирование: Xcode Instruments (watchOS), Android Studio Profiler + Filament stats (Wear OS).

**Trigger эскалации:** расход батареи в фоне > 3%/час → stop-the-line до исправления.

### R2. Античит в PvP и записи ударов ⚠️
**Проблема:** игроки подделывают удары, win-trade, эксплойтят экономику.

**Митигация (privacy-first, audit S1/S2):**
- Server-authority для всех исходов (бой, IAP, геном, мутации).
- Heart gate как главный шлюз записи удара (см. `MECHANIC_HEART_GATE.md`).
- **Privacy-safe античит** (см. `ANTICHEAT.md §3`): heart gate (60) + replay-detection с серверным nonce (15) + клиентская энтропия с проверкой диапазона (15) + rate-limit (10). **Серверной спектральной/гироскопической валидации НЕТ** — она физически невозможна без передачи сырого сигнала.
- Вероятностный аудит типа удара (распределение за 30 записей).
- Double-entry ledger для экономики с consistency check.
- Логирование всех подозрительных событий → ревью.

**Trigger:** > 1% SUSPECT-записей → добавить новые эвристики.

### R3. ~~Двойная клиентская разработка~~ → РЕШЕНО; новый: R16 Samsung partner approval ⚠️
**Прежняя проблема (РЕШЕНО audit S3):** Unity + SwiftUI = 2 команды, разные рантаймы. Решение: Unity заменён на нативный Kotlin+Filament. Оба клиента нативные, арт-пайплайн унифицирован (Rive skeletal animation как источник).

**Новый top-риск R16 (заменил R3 в top-5):** Samsung Health Sensor SDK partner approval — single point of failure для realtime HR на Wear OS → для всего USP-1 (запись ударов).

> 🚨 **Исправление аудита: заявленного fallback не существует.** Прежняя формулировка
> обещала «degraded Dojo без realtime HR, карта Common». Это неверно по двум
> независимым причинам:
>
> 1. **Гейт нельзя пройти.** `heartGate` требует `HR_present ≥ 0.80` в окне записи
>    5–8 секунд. `Sensor.TYPE_HEART_RATE` отдаёт значения с задержкой 5–15 секунд —
>    получить 80% валидных сэмплов в восьмисекундном окне физически невозможно.
> 2. **Карты Common не будет.** Без `heartGate` античит выдаёт REJECTED
>    (`ANTICHEAT.md` §3.0) — запись отклоняется целиком, карта не создаётся.
>
> Иными словами: **отказ Samsung означает не ухудшение USP-1 на Galaxy Watch,
> а его полное отсутствие.** Это надо знать до начала производства, а не после.

**Митигация (реальная, не декларативная):**
- Подать заявку **в первую неделю Sprint 0** (`MVP.md` Gate 3) — срок рассмотрения
  Samsung не контролируется нами.
- Параллельно проверить на реальном Galaxy Watch фактическую задержку и частоту
  `Sensor.TYPE_HEART_RATE`. Если на конкретных моделях она окажется ≈1 Гц —
  fallback становится возможным, и это меняет оценку риска. **Замерить, а не предполагать.**
- Подготовить решение на случай отказа (выбрать до конца Sprint 0):
  **(а)** watchOS как первая платформа вместо Wear OS (там путь к HR известен и открыт);
  **(б)** Dojo только на watchOS, Galaxy Watch получает остальной геймплей;
  **(в)** пересмотр heart gate под доступную частоту сэмплирования — с осознанным
  ослаблением античита и записью этого решения в `ANTICHEAT.md`.

**Trigger:** нет одобрения через 4 недели → активировать выбранный план (а/б/в),
переоценить timeline и скоуп MVP.

### R4. Ретеншн после новизны ⚠️
**Проблема:** классический тамагочи-эффект — бросают через 2 недели.

**Митигация:**
- **Бридинг** как долгая цель (3–8 недель на поколение, бесконечная мета).
- **Симбиоз** формирует привычку (возвращаешься «отметиться» активностью).
- **Сезоны** каждые 4 недели — новый контент, BP, ивент.
- **Социальные** лиги/турниры — стимул не выпадать.
- LiveOps-команда с оперпланом на 12 месяцев.

**Gate (Soft Launch):** D7 ≥ 15%. Если ниже → пересмотреть контент-план, добавить long-term goal.

### R5. Compliance (COPPA/GDPR-K) ⚠️
**Проблема:** возможная детская аудитория → жёсткие правила сбора данных.

**Митигация:**
- Юридический ревью на pre-production.
- Age-gate при регистрации (если <13 — COPPA-режим без сбора health-данных).
- Parental consent flow для детей.
- Прозрачная политика конфиденциальности.
- GDPR: экспорт/удаление данных по запросу.
- App Store Kids Category — опционально, если решим позиционироваться для детей.

## 4. ДЕГРАДИРОВАННЫЕ РЕЖИМЫ (graceful degradation)

Когда что-то идёт не так, игра должна деградировать мягко:

| Ситуация | Поведение |
|---|---|
| Нет сети | Офлайн-уход (кормить/чистить/тренировать), sync при reconnect |
| Нет Health-доступа | Базовый режим (~60% прогресса), без штрафов |
| Нет пульс-сенсора | Dojo недоступен, остальной геймплей работает |
| Сервер даун (бой) | Дружественное сообщение, не блокирует часы |
| Слабое устройство | Снижение FPS до 30, упрощённые шейдеры, меньше частиц |
| Плохой контакт часов | Soft-retry в Dojo, не блокировка |
